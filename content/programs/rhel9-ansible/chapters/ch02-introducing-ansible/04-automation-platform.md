## Three ways to get Ansible

{% cards cols=3 %}
  {% card kicker="Upstream" title="Community Ansible" tone="gray" %}
    Two `pip` packages from the upstream project:
    - **Ansible Core**: the runtime plus the `ansible.builtin` collection.
    - **community Ansible**: Ansible Core plus a community-selected set of collections.

    Not supported by Red Hat.
  {% /card %}
  {% card kicker="In RHEL 9" title="ansible-core RPM" tone="blue" %}
    Ships in the RHEL 9 AppStream repository. Supported, but **only** for content provided or generated by Red Hat products, such as `rhel-system-roles`, Insights remediation playbooks and OpenSCAP playbooks.
  {% /card %}
  {% card kicker="Fully supported" title="Automation Platform 2" tone="coral" %}
    Ansible Core plus certified collections, `ansible-navigator`, execution environments, automation controller, automation hub and cloud services. This is what the course (and this guide) uses.
  {% /card %}
{% /cards %}

{% callout type="important" title="Which version this guide targets" %}
The course is built on **Ansible Automation Platform 2.2**, which includes **Ansible Core 2.13**. That is roughly equivalent to the community "Ansible 6" distribution, with different collections and extra tools. Everything you learn applies to community Ansible too.
{% /callout %}

## What you get with Automation Platform

A subscription adds a set of things that enterprises care about:

- Official support for the core Ansible toolset.
- Red Hat **certified content collections** (more than 120 of them) with supported code.
- On-premise tools to centralise automation content, manage automation tasks, and scale out how automation runs.
- Cloud services for discovering certified content, collaborating as a team, and analysing automation across hybrid environments.

## The components of AAP 2

Click a component to see what it does. The **execution environment** at the centre is the idea that ties AAP 2 together.

{% diagram ref="platform-components" /%}

### Ansible Core

The fundamental functionality: the YAML automation language, loops, conditionals and the other building blocks of playbooks, plus the basic command-line tools. AAP 2.2 provides Ansible Core 2.13 in the `ansible-core` RPM and inside its `ee-minimal-rhel8` and `ee-supported-rhel8` execution environments.

### Ansible Content Collections

Ansible used to ship every module inside the core package ("batteries included"). As the number of modules exploded, that became hard to support, especially when people needed a newer or older version of one module than their Ansible version provided.

So modules moved into separate **Ansible Content Collections**: bundles of related modules, roles and plug-ins maintained by the same group of developers. Ansible Core itself keeps only the small `ansible.builtin` collection, which is always available.

### Automation content navigator

`ansible-navigator` is the new top-level tool for developing and testing playbooks. It replaces and extends several older commands:

| Older command | ansible-navigator equivalent |
| --- | --- |
| `ansible-playbook site.yml` | `ansible-navigator run site.yml` |
| `ansible-inventory --list` | `ansible-navigator inventory --list` |
| `ansible-config dump` | `ansible-navigator config` |
| `ansible-doc ansible.builtin.dnf` | `ansible-navigator doc ansible.builtin.dnf` |

Crucially, it separates the machine you *work on* from the environment that *runs* the automation, by running playbooks inside a container.

### Automation execution environments

An **automation execution environment (EE)** is a container image that holds Ansible Core, Ansible Content Collections, and any Python libraries, executables or other dependencies your playbook needs.

When you run a playbook with `ansible-navigator`, you choose an EE to run it in. Once it works, you can hand the playbook *and the same EE* to automation controller and know that it has everything it needs to run in production. Custom EEs are built with `ansible-builder`.

### Automation controller and automation hub

**Automation controller** (formerly Red Hat Ansible Tower) is the central place to run enterprise automation, with a web UI and a REST API. **Automation hub** at `console.redhat.com` provides certified collections that you download with `ansible-galaxy` (for `ansible-navigator`) or through controller. Installing controller and hub is outside the scope of this course and the exam.
